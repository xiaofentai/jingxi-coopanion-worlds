# 在吗

## 0.5.0

- 雷达的调参搬到 World 页的「雷达」页签：配置页里只剩「用毫米波雷达判定」这一个开关，串口、距离、门限都不再挤在配置页上。
- 「雷达」页签 = 状态一行（点 + 文案 + 端口与距离）+ 七项输入 + 保存；文案、单位与范围由 Node 侧算好，前端仍是零构建的 `src/webui.js`。
- 新增 `radar.status` / `radar.save` 两个面板方法。保存后如果改了串口或模块距离，会立刻重启读串口的子进程，不必等 World 重启。
- 这几项改存 `<data>/are-you-there-radar.json`，不再进 `config.json`——World 声明的配置组会被控制台全部渲染进「配置」页签，平台没有「声明了但不显示」的开关。首次运行时用 `config.json` 里的同名键当一次初值，之后以文件为准。
- 面板的轮询只刷新状态行；用户改过还没保存时不会覆盖输入框。

## 0.4.1

- 打开雷达后，左栏导航与 World 总览列表会多出一颗「雷达」状态灯（`lamps`，控制台每 500 ms 刷新）：绿＝链路正常、黄＝连上了还没在范围内见到人、红＝串口开着但收不到数据或读到的人全在范围外、灰＝没连上；悬停给出端口与当前读数。雷达关掉时不出灯。
- World 页新增「雷达状态」面板（`panels` + 手写 ESM `src/webui.js`，零构建）：一颗点加一句话，每秒刷新一次，如「● 正常工作，有人　COM5 · 79 厘米有人」；没打开雷达时整行隐藏。文案与语气由 `radar.status` 在 Node 侧算好，面板与状态灯共用同一套判断。

## 0.4.0

- 简介改成第一句就点出三路信号：锁屏、键鼠、雷达；并写明雷达那颗硬件的制作后续会开源。
- README 新增「推荐怎么组合」：讲清三路信号是不等权的否决关系（锁屏 → 雷达没人 → 雷达有人 → 键鼠空闲），给出按场景的推荐开关与四个不建议的配法。
- 新增第三个信号：HLK-LD2402 24 GHz 毫米波人体存在传感器（USB 转 TTL，串口 115200 8N1）。它报 `OFF` / `distance:79` 两种行，能看到「屏幕不动、键鼠也不动但其实人在」这一类情况：读书、看 PDF、看纸质材料、用手柄。
- 判定顺序定为「锁屏 > 雷达 > 键鼠」：锁着就不看后面；雷达稳定报没人就判离开；雷达稳定报有人就当作在桌前，键鼠空闲不再算数；雷达没表态才轮到键鼠空闲。
- 雷达读数由随包发出的 `src/radar.ps1` 提供：常驻 PowerShell 枚举 USB 串口、按需写模块最大距离并保存、逐帧上报；拔掉后一秒重连，换 COM 号不用改配置。
- 新增 `radarEnabled` / `radarPort` / `radarMaxDistance` / `radarMaxCm` / `radarAbsentSeconds` / `radarBackSeconds` / `radarPassByNotify` / `radarQuietSeconds` 八项设置，均可热改。
- 「有人经过」单独一条事件：判为离开期间，雷达短暂看到人（短于 `radarBackSeconds`，默认 10 秒）只推「有人经过」，不改状态、不算回来。
- 雷达漏检保护：雷达报没人、但键鼠在 `radarQuietSeconds`（默认 60 秒）内动过时，不判离开——坐着没动、被遮挡、微动门限偏高都会让雷达漏检。
- 距离自检：只把 `radarMaxCm`（默认 120 cm）以内的人算作在桌前；如果这次连接里从没在范围内见到人，雷达不参与判定，并在 `here.state` / `here_status` 里说明原因，避免模块参数被重置后反而把坐着的人判成离开。
- 雷达读数一秒六帧，迟滞在帧流里做完，不再要求连续两次轮询一致；锁屏那条路照旧。
- `here_status` 多一行雷达状态：端口、多少厘米、多久没测到人、没连上的原因。
- 环境提示的「不在」多一种原因 `radar`；`here.state` 会在括号后追加雷达补充（`，雷达在 79 厘米` / `，雷达没连上`）。
- README 新增「硬件：HLK-LD2402」：接线、两种供电版本（3.3 V 直供与 5 V 带 LDO，接错会烧）的分辨办法、驱动、参数含义（最大距离 / 目标消失延迟 / 触发与微动门限的 dB 换算）与调不准时的处理。

## 0.3.0

- 键鼠空闲到阈值时多一步判定，三项各自有开关：`checkLock`（用不用锁屏）、`checkForeground`（看一眼前台窗口）、`checkScreen`（比较两帧画面）。
- 前台判定读进程名与窗口标题，命中 `mediaKeywords`（默认是常见的视频与直播站）就当作在看东西，不判离开。只看名字，不拍画面。
- 画面判定隔约两秒截两帧，缩成 64×36 后逐像素比较，差异超过 2% 算「屏幕在变」。画面只在子进程内存里，不落盘。
- 两项都没认定时仍判离开；离开事件里会补一句「屏幕也没在变（差 0.4%）」。
- 三项判定默认全开（`checkLock` / `checkForeground` / `checkScreen`），用户可按需关掉。
- 市场标签加 `sensitive-data`（读取隐私）：空闲判定会读前台窗口标题与屏幕画面。简介写明全在本机计算——截图只在内存里做差分，不落盘、不发送、没有模型调用。
- 判定结果缓存 5 分钟，一直空闲时不会每隔十几秒重截一次屏。
- `here_status` 多一行判定结论。
- 修：PowerShell 输出改强制 UTF-8，否则中文窗口标题在 Node 里是乱码、关键词匹配不上。

## 0.2.0

- 新增第二个信号：键盘鼠标空闲时长。解锁着但键鼠连续 `idleMinutes`（默认 10 分钟）没有输入，也判成不在，原因记为 `idle`。
- 判定拆成 `decidePresence`（两个信号合成一次读数）与 `applyReading`（状态机），状态里多记 `reason`：`lock` 或 `idle`。
- 空闲读数由随包发出的 `src/idle.ps1` 提供：一个常驻 PowerShell 每两秒报一次 `IDLE <ms>`，World 停掉时一并杀掉；失败会退避重试，读数超过 60 秒没更新就当作读不到。
- 环境提示会写明「不在」的原因（锁屏 / 键鼠久无输入）；`here_status` 多一行空闲时长与阈值。
- 旧记录（0.1.0 写的 `locked`）读取时自动迁移为 `away` + `reason: lock`。

## 0.1.0

- 新增 World `are-you-there`（显示名「在吗」）：定时查一次屏幕锁没锁，把「ta 现在在不在桌前」作为 `here.state` / `here.lastAway` 两个环境提示变量交给系统前缀。
- 锁定判定用 `Windows` 锁屏时拉起的 `LogonUI.exe`：`tasklist` 一次调用几毫秒，不引原生模块、不联网、不碰用户目录。
- 读数要连续两次一致才算数；`tasklist` 失败或超时只记次数，不改变状态。
- 状态变化推 `are-you-there.changed` 事件（锁屏、解锁各一条，可分别在设置页关掉）；解锁那条附上这次离开了多久。
- 工具 `here_status`：报当前状态、持续时长、上次离开，并当场再查一次锁屏做核对。只读。
- 运行记录写在 `<data>/are-you-there.json`（原子改写），重启后仍知道「这个状态从什么时候开始」。
- 只在 Windows + Coopanion 上验证过；其他平台探针直接回「读不到」，不报错。
- `package.json` 加 npm 的 `os: ["win32"]`，扩展市场据此显示「仅 Windows」并按平台拦安装；`cortico.tags` 定为 `companion`（陪伴），`memory` 之类的既有 id 见官方 `index.json`。
- 文案里指代使用者统一写「ta」（英文用 they），简介改成与记忆卡同一写法的陈述句，全角标点。
