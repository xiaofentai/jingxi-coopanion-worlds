# world-are-you-there

显示名「在吗」，一个 Cortico World 扩展。三路信号一起看 ta 在不在：**屏幕锁没锁**、**键鼠还有没有动静**、**桌前有没有人**。第三路可选，接一颗 24 GHz 毫米波人体存在传感器（HLK-LD2402，USB 转 TTL 串口）；它能把「屏幕不动、键鼠也不动但其实人在」这一整类认出来——坐着读书、看 PDF、看纸质材料、用手柄。空闲到阈值时还能再判断一次「是在看东西还是真走了」。结论写进环境提示，状态变化时推一条事件。

雷达那颗硬件的制作（BOM、外壳、接线）后续会开源。

> 为 Windows 的锁屏与输入机制编写，只在 Windows + Coopanion 上验证过。裸 Cortico 部署、macOS 与 Linux 都未测试。

写它的原因：bot 不知道你是不是在。它在锁屏之后照样说话、照样等你回，回头才发现那句话对着空气讲完了。

所有判断都在本机完成：读屏幕锁、读前台窗口名、截两帧做像素差分、读串口上的雷达帧。没有模型调用，画面不出内存、不落盘、不发出去。

## 它怎么知道 ta 在不在

三层，按证据强弱排，前一层成立就不看后面：

**第一层，锁屏**

Windows 锁屏时会拉起 `LogonUI.exe`，解锁后它退出，看一眼这个进程就够。锁着就是不在，别的信号一律不参与。

**第二层，雷达（可选，默认关闭）**

接一颗 HLK-LD2402，串口 115200 8N1、每 165 ms 一帧。它只报两件事：`OFF`（范围内没人）和 `distance:79`（有人在 79 cm）。

- 稳定报「没人」就判离开 —— 比键鼠空闲硬得多：人走了但刚敲过键盘，键鼠要干等十分钟。
- 稳定报「有人」就判在桌前，键鼠空闲不再算数。这正是雷达要补的洞。
- **键鼠还热着就不信它**：雷达会漏检（坐着没动、遮挡物挡了一下、微动门限偏高），所以它报没人时还要求键鼠安静够久（默认 60 秒）。手在键盘上，就是人在。
- 它只在「这么近」（默认 120 cm）有人时才算数，房间另一头的家人不算。
- 短暂出现又消失的（没够上 `radarBackSeconds`，默认 10 秒）不当作回来了，只推一条「有人经过」。

**第三层，键鼠空闲**

解锁着但键盘鼠标连续 `idleMinutes` 没有动静，也先当作可能离开。雷达没装、没连上、或还没在范围内见到过人时，这一层独自工作。

空闲到阈值时还可以再判一次（默认关闭）：

- **看前台窗口**：读一次前台进程名与窗口标题，命中关键词（默认是常见视频与直播站）就当作在看东西，不判离开。只看名字，不拍画面。
- **比较两帧画面**：隔约两秒截两帧缩略图，缩成 64×36 后逐像素比较；差异超过 2% 就当屏幕在变，同样不判离开。画面只留在子进程内存里，不落盘、不发出去。

两项都没认定「在」，才判离开。判定结果保留 5 分钟，一直空闲时不会每十几秒重截一次屏。

宿主没有系统事件可以订阅，只能按配置的间隔轮询。读数要连续两次一致才算数（雷达是个例外：它一秒六帧，迟滞已经在帧流里做完），所以状态变化最多慢两个轮询间隔；读不到时保持原状，不会把一次失败当成「ta 回来了」。

## 什么时候会误判

那几个开关的根子是同一件事：**屏幕在变只证明有程序在动，屏幕静止也不证明没人在看**。所以两边都会错。

### 屏幕在变，但其实人走了（被误判成「在桌前」）

- **聊天软件一直来消息**：列表滚动、头像闪，屏幕持续在变。
- **直播或视频挂着人离开**：自动连播、循环播放，画面一直在动，关键词还命中。
- 广告、弹窗、托盘通知、动态壁纸（Wallpaper Engine 之类）。
- 下载进度、编译输出、`tail` 日志这类有持续输出的窗口。
- 游戏挂机、网页 GIF、音乐可视化。
- **桌宠自己**：它是常驻动画，只要它在屏幕上动，全屏差分就永远不是 0。实测静止画面在 1.1%–1.9%（阈值 2%），但桌宠动画大一些时可能越过阈值。

### 屏幕静止，但其实人在（被误判成「不在」）

- 读书、看 PDF、看长文档、看图：屏幕不动，键鼠也不动。
- 视频暂停、监控画面、单页漫画、幻灯片翻到某页。
- **用手柄玩游戏**：`GetLastInputInfo` 只统计键盘和鼠标，手柄、方向盘、MIDI 键盘都不计入。
- 看纸质材料、开会、打电话：人在桌前，但没碰电脑。
- 用另一台机器，或视频放在副屏：只截主屏，主屏静止就判离开。

> 装了雷达的话，这一整类基本都能认出来——它不看你碰没碰电脑，只看桌前有没有人。剩下的是「人在屋里但不在电脑前」，见下面雷达自己的边界。

### 信号自身的坑

- **只截主屏**：副屏在放视频，主屏静止 → 判离开。
- **2% 阈值**：画中画小窗、只有字幕或弹幕在变，可能够不到阈值 → 判离开。
- **DRM 内容**（Netflix 一类）：截出来是黑的，差分 0，只能靠关键词兜底。
- **远程桌面**：连过去会把本机会话锁上 → 判离开。语义没错，但人可能就坐在这张桌前。
- **屏保没勾「恢复时显示登录屏幕」**：屏幕黑了但没锁，判「在」。
- **两帧只隔 1.8 秒**：视频刚好在缓冲，或刚好切场景，这一跳的结果会随机。

### 雷达自己的坑

- **它测的是「有人在探测范围内」，不是「人在电脑前」**：躺在床上、坐在同一间屋子的另一头，只要在范围内都算有人。这是它最根本的边界，靠 `radarMaxCm` 收窄只能缓解。
- **静止检测靠微动能量**：人几乎不动时，雷达靠呼吸、心跳带来的毫米级位移撑着。桌下、被遮挡、或者微动门限偏高，能量掉到门限以下，模块就开始倒计时，`目标消失延迟`（出厂 30 秒）一到就报 `OFF` —— 人明明坐在那儿。
- **模块最大距离会被断电重置**：出厂 8.5 m，覆盖整个房间加门外走廊。插件启动时会把它写成配置里的值并保存；万一写失败，你会在 `here.state` 里看到「雷达在 1.5 米以外」这种明显不对的距离。
- **距离不是坐标**：一个距离门 70 cm，测距精度 ±0.15 m，同一个坐姿下读数会在 74–85 cm 之间跳（测到的是腿、椅子、身体不同部位）。别拿它判断「离屏幕多远」。
- **遮挡物不能自己动**：摆动的窗帘、风口的大株绿植、会飘的塑料袋，都会被当成有人。
- **串口是独占的**：海凌科上位机开着的时候插件连不上，`here.state` 会写「没连上」。

结论：默认只保留锁屏与键鼠两个信号，误判明显更少。这两项判定适合你自己清楚在看什么的时候手动开。雷达能把「屏幕静止但其实人在」那一整类误判补掉，代价是上面那几条新的边界。

### 其他边界

- 开机后的登录界面上 `LogonUI.exe` 也在跑。Coopanion 是登录之后才起的，第一次读数多半已经准确；如果启动时正好在登录界面，会记成「不在」，解锁后自然纠正。
- UAC 的安全桌面走 `consent.exe`，不会误判。
- 没勾「在恢复时显示登录屏幕」的屏保不会锁屏，因此也不算离开——那本来就是「ta 在、屏幕亮着」。
- 快速用户切换会让你这个会话锁上，判定为离开，语义正确。
- 空闲读数靠一个常驻 PowerShell 进程（每两秒取一次 `GetLastInputInfo`）。它退出会自动重起，读数超过一分钟没更新就当作读不到。
- 雷达也靠一个常驻 PowerShell 进程读串口。拔掉 USB 会让它读失败、退出、一秒后重连；插回去一两秒恢复，换到别的 COM 号也不用改配置。超过 5 秒没有新帧就当作读不到。
- 打开雷达后，插件**会写模块的最大距离参数**（「雷达」页签里的「模块探测距离」，默认 1.4 m）并保存进模块。这是唯一一处对硬件的写操作，把它设成 0 可以关掉。
- 只支持 Windows；其他平台这几项检查都读不到，退化成只看锁屏。

## 推荐怎么组合

三路信号的强弱是**不等权**的，不是投票：锁屏单独成立就够，雷达单独成立也够，键鼠空闲只在雷达没表态时才用。所以「交叉判断」的意思是**谁否决谁**，不是凑票数。

判定的实际顺序（细节见上一节）：

```
锁屏 → 雷达「没人」→ 雷达「有人」→ 键鼠空闲
```

两种「有人」的证据（前台窗口、两帧差分）只挂在**键鼠空闲**那一路做复核，雷达判离开时不参与——「挂着视频人走了」正是它们会漏的情况。

### 推荐配置

| 你的情况 | 开哪几路 | 关键参数 |
|---|---|---|
| **没接硬件**（默认） | 锁屏 + 键鼠 | `idleMinutes` 按习惯调；`checkForeground` / `checkScreen` 保持关闭 |
| **接了雷达（推荐）** | 锁屏 + 雷达 + 键鼠宽限 | `radarEnabled` 打开；`radarMaxDistance` 14、`radarMaxCm` 120；`radarQuietSeconds` 60 |
| 雷达调得准、想更灵敏 | 同上，宽限期收紧 | `radarQuietSeconds` 30；`radarAbsentSeconds` 5 |
| 房间里常有别人在探测范围内 | 锁屏 + 雷达，距离收紧 | `radarMaxDistance` 7 或 14（一个距离门 70 cm）；`radarMaxCm` 比它略小 |
| 长时间看视频、桌面常有人 | 锁屏 + 键鼠 + 前台窗口 | `checkForeground` 打开，关键词按需加减 |
| 只想被叫「ta 走了」，不想被叫「ta 回来了」 | 任意组合 | `notifyBack` 关掉；`radarPassByNotify` 也关掉 |

### 不建议这样配

- **`radarQuietSeconds` 设 0 + 微动门限没调过**：人坐着不动时雷达会漏检，漏检直接判离开。要么留宽限期，要么先把门限调好。
- **雷达和上位机同开**：串口独占，插件会一直报「没连上」，而且此时只有锁屏在起作用。
- **`checkScreen` 和桌宠同开**：桌宠是常驻动画，画面一直在变，等于永远判「在看」。
- **`radarMaxCm` 大于 `radarMaxDistance`**：模块根本不会报那么远，这个上限就白设了，自检也会失效。

## 配置（`worlds.are-you-there.*`）

这一页只留开关与两个数字，细节都在「设置」页签里：

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 装完要显式打开 |
| `pollSeconds` | `15` | 多久查一次，5–300 秒；改完下一跳生效，不用重启 |
| `checkIdle` | `true` | 单独用键鼠空闲判离开的开关。**打开雷达时这一路自动停用**，键鼠只作为雷达的交叉证据 |
| `idleMinutes` | `10` | 键鼠连续多久没输入算离开；`0` 表示不看这个信号 |
| `checkLock` | `true` | 用锁屏判定；关掉后完全忽略锁屏 |
| `radarEnabled` | `false` | 用毫米波雷达判定。**它的参数不在这里**，见下一节 |
| `notifyAway` | `true` | 判为离开时推事件 |
| `notifyBack` | `true` | 回到桌前之后推事件，附上这次离开了多久 |

### 细节在「设置」页签里

前台窗口、关键词、两帧差分、雷达那几项都不放配置页——World 声明的配置组会被控制台**全部**渲染进「配置」页签，平台没有「声明了但不显示」的开关。所以它们搬到了 World 页的「设置」页签，分成两张可折叠的卡：

- **空闲判定**：看前台窗口（**打开后才出现关键词输入框**）、比较两帧画面。
- **雷达**：状态一行 + 串口、距离、门限七项。**雷达开关关着时这张卡里只有一句说明**，没有可调项。

改完自动保存（停手 0.6 秒），存在 `<data>/are-you-there-settings.json`（不进 `config.json`）：

| 键 | 默认 | 说明 |
|---|---|---|
| `checkForeground` | `false` | 空闲时看前台窗口，命中关键词就不判离开 |
| `mediaKeywords` | 见上 | 关键词，逗号分隔。只在 `checkForeground` 打开时才出现在界面上 |
| `checkScreen` | `false` | 空闲时比较两帧画面，屏幕在变就不判离开（会拍屏幕） |
| `radarPort` | `auto` | 串口号；`auto` 表示每次连接时自己枚举 USB 串口，插拔换号也能接上 |
| `radarMaxDistance` | `14` | 写进模块的最大探测距离，0.1 m 单位（14 = 1.4 m），7–100。启动时读、不一致就写回并保存；`0` 表示不动模块 |
| `radarMaxCm` | `120` | 只把这么近的人算作在桌前，厘米。同时是自检基线 |
| `radarAbsentSeconds` | `5` | 模块报「没人」**之后**再等多久算离开。见下面「延迟是叠起来的」 |
| `radarBackSeconds` | `10` | 雷达连续测到人多久才算回来；更短的算路过 |
| `radarPassByNotify` | `true` | 判为离开期间，短暂看到人就推一条「有人经过」 |
| `radarQuietSeconds` | `35` | 键鼠至少安静这么久才考虑信雷达；实际窗口会跟着雷达漏检时长一起变长，见下面。`0` 表示完全听雷达的 |

### 延迟是叠起来的，还有一条会盖住它们

三段时间是**串联**的，不是三选一：

```
人离开 ──30 秒──▶ 模块开始报 OFF ──radarAbsentSeconds(5)──▶ 判离开 ──(radarQuietSeconds)──▶ 推事件
```

- 前 30 秒是模块自己的「目标消失延迟」`0x0004`，插件改不了它，也不该把这 30 秒算进 `radarAbsentSeconds`——那一项是**在这之上**再加的。
- 所以默认是 `30 + 5 = 35 秒`。插件会读模块的 `0x0004`：**「多久没人算离开」那一行右端会挂个小标「合计 35 秒」**，雷达卡底下写一句「LD2402 的硬件延迟是 30 秒」；`here_status` 里那句「雷达已经 35 秒没测到人」也是这个总数，不是插件等的那 5 秒。串口没连上读不到硬件延迟时，小标不出现，卡底那句改成解释两者要相加。
- `radarQuietSeconds`（默认 35）是雷达这一路**内部的键鼠交叉门**：雷达报没人满 35 秒时，还要键鼠也静默满 35 秒才判离开。键鼠短暂动几秒不算数——静默够了照样判走；但 35 秒内动过，就再等等。设 0 表示完全听雷达的。
- 雷达**这一路自己闭环**，不和独立键鼠判定叠加。雷达打开时 `checkIdle` 那一路自动停用，键鼠读数只用来做上面这次交叉验证；两边同时开会互相打架。

### 完整判定表（按优先级，命中即停）

| 情况 | 结论 |
|---|---|
| 锁屏 | **离开**（原因 `lock`），雷达说有人也不推翻 |
| 雷达连续有人 ≥ 5 秒 | **在桌前**，不看键鼠、也不看空闲阈值——读书、纸质材料、手柄都靠这条补 |
| 雷达报没人 ≥ 5 秒（合计 35 秒）+ 键鼠静默 ≥ 35 秒 | **离开**（原因 `radar`），两边交叉成立 |
| 同上，但键鼠 35 秒内动过 | **不动**，等键鼠静默够了再交叉；短暂动几秒不算数 |
| 雷达报没人后有人影一闪（< `radarBackSeconds`，默认 10 秒） | 只推「有人经过」，状态不变 |
| 雷达没连上 / 帧过期 / 从没在范围内见过人 | 雷达**不表态**，退回独立键鼠那一路（若 `checkIdle` 开着） |
| 雷达关 + `checkIdle` 开 + 键鼠空闲 ≥ `idleMinutes` | **离开**（原因 `idle`），前台/差分复核照旧 |
| `checkIdle` 关 + 雷达关 | 只有锁屏能判离开 |

默认关键词：`bilibili,哔哩哔哩,youtube,netflix,twitch,vlc,mpv,potplayer,mpc-hc,mpc-be,爱奇艺,腾讯视频,优酷,芒果tv,抖音,douyin,斗鱼,虎牙,plex,emby,jellyfin`。

**升级**：`config.json` 里这些键不再被读取，只在设置文件还不存在时当一次初值。0.5.x 写在 `are-you-there-radar.json` 里的雷达参数会被读一次搬过来，之后以 `are-you-there-settings.json` 为准。

## 环境提示变量

| 变量 | 内容 |
|---|---|
| `here.state` | 在不在、从什么时候开始、为什么判成不在，如 `不在（11-09 15:10 键盘鼠标久无输入，已 12 分钟）`；装了雷达还会追加一句，如 `在桌前（11-09 15:22 解锁，已 8 分钟；雷达在 79 厘米）` 或 `，雷达没连上` |
| `here.lastAway` | 上一次离开的起止与时长，如 `11-09 14:32 → 11-09 14:58，26 分钟` |

这两个变量在每次交接重建前缀时重新生成。session 中途的变化靠事件，不靠前缀刷新。默认模板可以在控制台「提示词」页的 `worlds.are-you-there.envPrompt` 里改。

## 事件

锁屏、空闲、雷达、路过、回来各一条：

- `屏幕在 11-09 14:32 锁上了：ta 离开了电脑。`
- `键盘鼠标已经 12 分钟没有动静，屏幕也没在变（差 0.4%）：ta 大概不在屏幕前了。`
- `雷达已经 35 秒没测到人，最近一次在 79 厘米：ta 大概离开桌前了。`
- `雷达看到有人经过桌前（停留 3 秒，最近一次在 84 厘米）：大概不是 ta 回来，状态没变。`
- `屏幕在 11-09 15:44：ta 回来了，这次离开了 1 小时 12 分钟。`
- `雷达在 11-09 15:44 又测到了人：ta 回到桌前，这次离开了 1 小时 12 分钟。`

启动后第一次读到状态不推事件，免得每次开应用都喊一句。

## 工具

`here_status`：报当前状态、持续了多久、上次离开了多久、键鼠空闲了多久、雷达连没连上／在多少厘米／多久没测到人、上一次空闲判定的结论，并当场再查一次锁屏，说明读到的与记录是否一致。

## 硬件：HLK-LD2402

海凌科的 24 GHz 静止人体存在传感器，20×20 mm，串口 115200 8N1，正常模式每 165 ms 一行 ASCII。接线（手册表 4-1）：

| 传感器 J2 | USB 转 TTL |
|---|---|
| `R`（UART_RX） | TXD |
| `T`（UART_TX） | RXD |
| `G` | GND |
| `V` | 见下面「供电」 |

J2 还有一根 `IO`（有人时高电平），用不上，可以悬空。

### 供电：先确认手上这是哪个版本

这颗模块有**两种供电版本，接错会烧**，别照着别人的接线抄：

| 版本 | 板上有没有 LDO | `V` 要接 | 手册里的参数 |
|---|---|---|---|
| 3.3 V 版（出厂默认，未贴 LDO） | 没有 | **3.3 V** | 3.0–3.6 V，典型 3.3 V |
| 5 V 版（已加贴 LDO） | 有 | **5 V** | 4.5–5.5 V，典型 5 V |

分辨办法：看模块背面有没有一颗小线性稳压器（丝印多为 `662K`、`XC6206` 一类），或者直接看卖家标的型号/版本。拿不准就先用 3.3 V —— 3.3 V 接到 5 V 版上只是不亮或工作不稳，反过来会烧。

转接板的 `VCC` 要跟着选对应的档位：有 3.3 V/5 V 跳线或双输出的板子，别默认它给的是 3.3 V，用万用表量一下再插。

USB 口本身给的是 5 V，所以 **5 V 版可以直接从转接板的 VCC 取电；3.3 V 版必须走转接板的 3.3 V 输出**，不能直接吃 USB 的 5 V。

Win10/11 一般免驱（走系统自带 `usbser`）；老系统需要装 CH340 之类的厂商驱动。

装好之后在设置里打开「用毫米波雷达判定」，串口留 `auto`。插件会：启动时读模块的最大距离、和 `radarMaxDistance` 不一致就写回去并保存；连不上就退避重连，热插拔一两秒恢复；端口号每次重连都重新枚举。

打开之后，**左栏导航和 World 总览列表上会多出一颗「雷达」灯**，悬停写着 `雷达 状态 · 详细信息`，每 500 ms 刷新一次：

| 灯 | 意思 | 悬停能看到 |
|---|---|---|
| 绿 | 链路正常 | `COM5 · 79 厘米有人`，或 `COM5 · 已经 12 秒没测到人` |
| 黄 | 连上了，但还没在范围内读到人（此时不参与判定） | `COM5 · 连上了，但还没在范围内读到人` |
| 红 | 串口开着但收不到数据，或读到的人全在范围外 | `COM5 · 已经收不到新数据了（多半被拔了）` / 读到的人都在 120 厘米之外 |
| 灰 | 没连上 | 没插、端口被上位机占着、驱动没装 |
| （没有灯） | 没打开雷达 | — |

绿灯只说明**硬件在工作**，不代表人在：人走了雷达照常读数，灯还是绿的。

除此之外，**World 页里有一个「设置」页签**，判定细节与雷达调参都在里面，各一张可折叠的卡：

```
▼ 空闲判定
    空闲时看一眼前台窗口    ●        ← 关着时下面那行不出现
    认作「在看」的关键词    bilibili,哔哩哔哩,…
    空闲时比较两帧画面      ○

▼ 雷达
    状态                   ● 正常工作，有人    COM5 · 78 厘米有人（最近一帧 12:30）
    串口                   auto
    模块探测距离           14    0.1 米
    只把这么近的人算作在桌前 120  厘米
    多久没人算离开          5     秒
    多久有人才算回来        10    秒
    有人经过时推事件        ☑
    键鼠还热着就不信雷达    60    秒
```

- 卡头能点，折叠状态会记住。
- **「关键词」只在「看前台窗口」打开时出现**；**雷达开关关着时，雷达那张卡里只有一句「没有可调项」**。
- 改完停手 0.6 秒自动保存，和配置页一致；状态行随轮询刷新，不会覆盖你正在输的内容。

（页签的位置：左栏「World」→ 这个 World 的名字。页签顺序是「面板在前、配置在后」，所以默认落在「设置」上。）

页头还有三颗药丸，位置跟「联网 Pro」的工具调用计数那一排一样，进页面不用点页签就能看见：

```
雷达 已连接 | 状态 正常工作，有人 | 读数 79 厘米
```

它们读的是同一份判断（`radarStatus`），灯、页头、页签三处不会互相矛盾。雷达没打开时这三颗不出现。

**调不准的时候**，用海凌科上位机 `HLK-LD2402_Tool` 看「实时数据」页：

- **人坐着却被报 `OFF`** → 微动门限偏高。串口参数 `0x0030`（模式 0 的微动门限）是主因，出厂约 52 dB。可以在上位机里调低几 dB，或者挪一下传感器让它看到上半身/手臂，而不是只看到腿。注意上位机与插件抢串口，调的时候要先把插件关掉。
- **别人在屋里也被算成有人** → 把 `radarMaxDistance` 调小（一个距离门 70 cm，1.4 m 或 2.1 m 比较实用），并确认 `radarMaxCm` 比它略小。
- **生成门限**这个功能要求生成时房间里没有人，房间里有别人时用不了。

## 安装

在扩展页「手动安装 → 从 npm」里填 `world-are-you-there`，装完重启进程，再在 World 总览里打开「在吗」并确认轮询间隔、空闲阈值与几项判定开关。接了雷达的话，还要打开「用毫米波雷达判定」。
