# world-are-you-there

显示名「在吗」，一个 Cortico World 扩展：隔一会儿查一次屏幕锁没锁，把「ta 现在在不在桌前」写进环境提示，状态变化时推一条事件。

> 为 Windows 的锁屏机制编写，只在 Windows + Coopanion 上验证过。裸 Cortico 部署、macOS 与 Linux 都未测试。

写它的原因：bot 不知道你是不是在。它在锁屏之后照样说话、照样等你回，回头才发现那句话对着空气讲完了。

## 它怎么知道 ta 在不在

Windows 在工作站锁屏时会拉起 `LogonUI.exe`，解锁后它退出，所以看一眼这个进程在不在就够了。宿主没有系统事件可以订阅，只能按配置的间隔轮询。

读数要连续两次一致才算数，所以状态变化最多慢两个轮询间隔；读不到时保持原状，不会把一次失败当成「ta 回来了」。

### 已知边界

- 开机后的登录界面上 `LogonUI.exe` 也在跑。Coopanion 是登录之后才起的，第一次读数多半已经准确；如果启动时正好在登录界面，会记成「不在」，解锁后自然纠正。
- UAC 的安全桌面走 `consent.exe`，不会误判。
- 没勾「在恢复时显示登录屏幕」的屏保不会锁屏，因此也不算离开——那本来就是「ta 在、屏幕亮着」。
- 快速用户切换会让你这个会话锁上，判定为离开，语义正确。
- 只支持 Windows；其他平台 `here_status` 会直接说「只在 Windows 上能读」。

## 配置（`worlds.are-you-there.*`）

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 装完要显式打开 |
| `pollSeconds` | `15` | 多久查一次，5–300 秒；改完下一跳生效，不用重启 |
| `notifyAway` | `true` | 确认锁屏后推事件 |
| `notifyBack` | `true` | 确认解锁后推事件，附上这次离开了多久 |

觉得锁屏提示吵，就把「锁屏时推事件」关掉：状态照常更新，只是不再主动开口。

## 环境提示变量

| 变量 | 内容 |
|---|---|
| `here.state` | 在不在、这个状态从什么时候开始，如 `不在（11-09 14:32 锁屏，已 26 分钟）` |
| `here.lastAway` | 上一次离开的起止与时长，如 `11-09 14:32 → 11-09 14:58，26 分钟` |

这两个变量在每次交接重建前缀时重新生成，所以是那一刻的真实状态。session 中途的变化靠事件，不靠前缀刷新。

默认模板可以直接改：控制台「提示词」页里的 `worlds.are-you-there.envPrompt`，保存的版本盖过包里的。

## 事件

锁屏、解锁各一条：

- `屏幕在 11-09 14:32 锁上了：ta 离开了电脑。`
- `屏幕在 11-09 15:44 解锁了：ta 回来了，这次离开了 1 小时 12 分钟。`

启动后第一次读到状态不推事件，免得每次开应用都喊一句。

## 工具

`here_status`：报当前状态、持续了多久、上次离开了多久，并当场再查一次锁屏，说明读到的与记录是否一致。

## 安装

在扩展页「手动安装 → 从 npm」里填 `world-are-you-there`，装完重启进程，再在 World 总览里打开「在吗」并确认轮询间隔。
