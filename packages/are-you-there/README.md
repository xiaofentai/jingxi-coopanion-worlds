# world-are-you-there

显示名「在吗」，一个 Cortico World 扩展：隔一会儿查一次屏幕锁没锁、键盘鼠标还有没有动静，空闲到阈值时再判断一次「是在看东西还是真走了」，把结论写进环境提示，状态变化时推一条事件。

> 为 Windows 的锁屏与输入机制编写，只在 Windows + Coopanion 上验证过。裸 Cortico 部署、macOS 与 Linux 都未测试。

写它的原因：bot 不知道你是不是在。它在锁屏之后照样说话、照样等你回，回头才发现那句话对着空气讲完了。

所有判断都在本机完成：读屏幕锁、读前台窗口名、截两帧做像素差分。没有模型调用，画面不出内存、不落盘、不发出去。

## 它怎么知道 ta 在不在

两层：

**第一层，两个信号取或**

- **屏幕锁着**：Windows 锁屏时会拉起 `LogonUI.exe`，解锁后它退出，看一眼这个进程就够。
- **键鼠久无输入**：解锁着但键盘鼠标连续 `idleMinutes` 没有动静，也先当作可能离开。

**第二层，空闲到阈值时判一次**

这一层只在「解锁 + 键鼠久无输入」时触发，两项开关各自独立：

- **看前台窗口**：读一次前台进程名与窗口标题，命中关键词（默认是常见视频与直播站）就当作在看东西，不判离开。只看名字，不拍画面。
- **比较两帧画面**：隔约两秒截两帧缩略图，缩成 64×36 后逐像素比较；差异超过 2% 就当屏幕在变，同样不判离开。画面只留在子进程内存里，不落盘、不发出去。

两项都没认定「在」，才判离开。判定结果保留 5 分钟，一直空闲时不会每十几秒重截一次屏。

宿主没有系统事件可以订阅，只能按配置的间隔轮询。读数要连续两次一致才算数，所以状态变化最多慢两个轮询间隔；读不到时保持原状，不会把一次失败当成「ta 回来了」。

### 已知边界

- **看视频但键盘鼠标不动**：前台关键词与画面差分都能接住，这是这一层的主要用途。
- **读书、看 PDF、看图**：画面是静止的，两项都判不出「有人在」，仍会判离开。这类情况目前只能靠调大 `idleMinutes`，或者关掉空闲信号只看锁屏。
- **截图这一项默认开着，会拍你的屏幕**：画面只在子进程内存里做差分，不落盘、不外传，但确实读到了屏幕内容。介意就在设置里关掉。
- 开机后的登录界面上 `LogonUI.exe` 也在跑。Coopanion 是登录之后才起的，第一次读数多半已经准确；如果启动时正好在登录界面，会记成「不在」，解锁后自然纠正。
- UAC 的安全桌面走 `consent.exe`，不会误判。
- 没勾「在恢复时显示登录屏幕」的屏保不会锁屏，因此也不算离开——那本来就是「ta 在、屏幕亮着」。
- 快速用户切换会让你这个会话锁上，判定为离开，语义正确。
- 空闲读数靠一个常驻 PowerShell 进程（每两秒取一次 `GetLastInputInfo`）。它退出会自动重起，读数超过一分钟没更新就当作读不到。
- 只支持 Windows；其他平台这几项检查都读不到，退化成只看锁屏。

## 配置（`worlds.are-you-there.*`）

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 装完要显式打开 |
| `pollSeconds` | `15` | 多久查一次，5–300 秒；改完下一跳生效，不用重启 |
| `idleMinutes` | `10` | 键鼠连续多久没输入算离开；`0` 表示不看这个信号 |
| `checkLock` | `true` | 用锁屏判定；关掉后完全忽略锁屏 |
| `checkForeground` | `true` | 空闲时看前台窗口，命中关键词就不判离开 |
| `mediaKeywords` | 见下 | 前端判定的关键词，逗号分隔 |
| `checkScreen` | `true` | 空闲时比较两帧画面，屏幕在变就不判离开 |
| `notifyAway` | `true` | 判为离开时推事件 |
| `notifyBack` | `true` | 回到桌前之后推事件，附上这次离开了多久 |

默认关键词：`bilibili,哔哩哔哩,youtube,netflix,twitch,vlc,mpv,potplayer,mpc-hc,mpc-be,爱奇艺,腾讯视频,优酷,芒果tv,抖音,douyin,斗鱼,虎牙,plex,emby,jellyfin`。

## 环境提示变量

| 变量 | 内容 |
|---|---|
| `here.state` | 在不在、从什么时候开始、为什么判成不在，如 `不在（11-09 15:10 键盘鼠标久无输入，已 12 分钟）` |
| `here.lastAway` | 上一次离开的起止与时长，如 `11-09 14:32 → 11-09 14:58，26 分钟` |

这两个变量在每次交接重建前缀时重新生成。session 中途的变化靠事件，不靠前缀刷新。默认模板可以在控制台「提示词」页的 `worlds.are-you-there.envPrompt` 里改。

## 事件

锁屏、空闲、回来各一条：

- `屏幕在 11-09 14:32 锁上了：ta 离开了电脑。`
- `键盘鼠标已经 12 分钟没有动静，屏幕也没在变（差 0.4%）：ta 大概不在屏幕前了。`
- `屏幕在 11-09 15:44：ta 回来了，这次离开了 1 小时 12 分钟。`

启动后第一次读到状态不推事件，免得每次开应用都喊一句。

## 工具

`here_status`：报当前状态、持续了多久、上次离开了多久、键鼠空闲了多久、上一次空闲判定的结论，并当场再查一次锁屏，说明读到的与记录是否一致。

## 安装

在扩展页「手动安装 → 从 npm」里填 `world-are-you-there`，装完重启进程，再在 World 总览里打开「在吗」并确认轮询间隔、空闲阈值与几项判定开关。
