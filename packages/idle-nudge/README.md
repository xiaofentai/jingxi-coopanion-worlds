# world-idle-nudge（小纸条）

她闲下来一阵之后，按设定的节奏推一条事件。三件事，共用插件、分开判据：

| | 早晚安 | 小纸条 | 静默心跳 |
|---|---|---|---|
| 作用 | 递一句让她发给 ta 的问候 | 递一句带动作的话 | 续上游前缀缓存 |
| 判据 | 两个时刻各一个点 ± 幅度，哈希抖动，一天一条 | 距上次**推纸条**够久 + 落在三个可配时段之一 + 该段当天有名额 | 距上次**模型调用**超过阈值（读 `usage.jsonl` 的 mtime） |
| 时段 | 两个时刻，留空不启用 | 只有三段可配窗口 | 全天 |
| 正文 | 固定由头，措辞和通道由她定 | 带动作，去不去做由她定 | 不要求回应 |
| 事件 type | `idle-nudge.greeting` | `idle-nudge.note` | `idle-nudge.beat` |

**为什么分开**：后台信息（星邮推桌等）会不断刷新 `usage.jsonl` 的 mtime；纸条和问候若也看 mtime 就永远等不到空档。它们只数自己的钟。心跳全天，纸条只在白天，问候按你填的两个时刻。

**同一拍多套都通过时**：按 问候 > 纸条 > 心跳 取一条。那一拍也唤醒模型，缓存照样续上；把心跳的计时记成现在，不再补第二条。

## 早晚安

- 开关 `greetingEnabled` 默认关；开了但时刻留空仍不生效。
- 两行：早安时刻、晚安时刻。每行左边填时刻（`7:30` / `23`），右边填双向抖动幅度（分钟，默认 20）。
- 当天在这个范围内哈希挑一个点（同一天稳定、隔天换），一天一条；过了窗口不补，防止半夜补昨晚的晚安。
- 跨零点的那一拍不会把「今晚 23:35 的目标」当成「刚过去」（0.2.9 修的：之前 00:00:09 会白补一条）。代价是目标点落在 00:0x 的那天不补，等第二天按新日期的目标走。
- 正文**不给用户填**，是固定由头（`GREETING_HINT`）——只递"该道早安/晚安了"这件事，措辞由她自己想，不替她写话：

```
（系统给的由头，不是 ta 刚说的话。）现在{time}，该道{who}了——用你自己的话跟 ta 说一句，走你平时开口的通道。别回这条、别解释。
```

不绑定具体通道 World——哪个 World 提供开口的通道就用哪个。`{time}` 是抖动后真正发出去的时刻。写成陈述式且明说"别回这条"——问句会诱使她用气泡回答那条提示。

它不写盘、不给工具、不进前缀、不调用别的插件的工具。运行时状态（上次推的时刻、今天推了几次）不落自己的文件，但每拍会去**宿主的事件库**核对自己今天推过什么——所以重启不清零，也不会重复推。

## 正文

心跳默认：

```
静默心跳{time}，无需回复。
```

纸条默认（身份标记别删，否则她会当成 ta 在搭话后用气泡回复）：

```
（系统递的空闲提醒，不是 ta 说的，不用回这条。）现在{time}啦——花花草草小动物、玩玩游戏、找人或者别的鱼聊两句，想干哪样就直接调工具去做；要跟 ta 开口走平时那条通道（微信 / 气泡）；都不想就安静。
```

写成陈述式而不是 `要不要…？`——问句会被当成有人在跟她说话，她就用气泡回答了。正文明确告诉她：不用回这条、要做就调工具、想跟 ta 开口走微信 / 气泡。

`{time}` 换成当前时刻。两段正文都可在设置页改；留空＝用默认。

## 抖动

纸条不是一进时段就推：`note.ts` 按「日期 + 段号 + 第几张」哈希出当天这一段的抖动点，在窗口内随机一个时刻。同一天重启不漂，隔天自动换；`perDay > 1` 时几张分别落在窗口的几份里，不会挤在一起。抖动点没到时，「现状」卡会显示约在几点。

## 设置

配置页只有一个 `enabled` 开关；其余参数在「设置」页，和开关同住 `config.json` 的 `worlds.idle-nudge.settings` 段。改完下一拍生效，不用重启。

保存是**严格**的：写坏了当场报错（`9-25`、`25:00`、`9-`、`9-9`、看表间隔 1、每日上限 999、正文超 500 字…），这一份一个字都不存，报错显示在面板底部、输入框内容保留。不会像 0.2.6 之前那样悄悄改回旧值还显示「已保存」。读盘仍是宽松的（手改坏的 `config.json` 会退回默认，插件照常起来）。

写盘和宿主一致：**整份 `config.json` 解析不了就拒绝保存**，文件一个字不动，等你手工修（不会拿空对象重建，把别的 world 的段抹掉）；文件不存在才当作新装建一份。

| 键 | 默认 | 说明 |
|---|---|---|
| `greetingEnabled` | **false** | 早晚安总开关（卡片首行），不需要就关 |
| `heartbeatEnabled` | **false** | 静默心跳的总开关（卡片首行）。默认关——命中不够便宜、或 TTL 不稳定的模型开了反而更贵，不确定就别启用 |
| `noteEnabled` | true | 小纸条的总开关（卡片首行） |
| `idleMinutes` | 40 | 心跳空档阈值。LongCat-2.5 的实测值，换上游先量 |
| `maxPerDay` | 48 | 心跳日上限，0 = 不限 |
| `tickSeconds` | 15 | 多久看一次表 |
| `heartbeatText` | 见上 | 心跳正文，留空用默认 |
| `slots` | `9-12`×1 / `14-18`×1 / `19-22`×1 | 三段窗口，设置页每行两个并排框：左边时段、右边张数；时段留空＝不启用，可跨零点 |
| `noteGapMinutes` | 120 | 两张纸条之间至少隔多久（跨段共用） |
| `noteText` | 见上 | 纸条正文，留空用默认 |

设置页顺序：小纸条 → 早晚安 → 静默心跳 → 现状。三个功能各有自己的开关在卡片首行，关掉一个不影响另一个；正文框的提示里写着默认句长什么样。页头药丸显示三个功能各自今天推了多少、缓存距今多久。

## 判据

心跳（`beat.ts`）：

1. 上一拍刚推过 → 不推（自己不能把自己催起来）
2. 距上次调用不够 `idleMinutes` → 不推
3. 今天推满 `maxPerDay` → 不推

纸条（`note.ts`）：

1. 现在不在任何启用的时段 → 不推
2. 落在的时段今天名额用完 → 不推
3. 当天的抖动点还没到 → 不推
4. 距上一张纸条不够 `noteGapMinutes` → 不推

**「今天推过没有」查事件库，不靠内存**：每次推送带稳定 `senderKey`（`note:0` / `greeting:1` / `beat`）。仍然是内存先判，**只有判据要推的那一刻**才用 `host.store.range` 查一次（同步、按 `source` 过滤、只看 26 小时内），查到的结果写回内存并重判——同一件事最多查一次。所以重启不会重复推、晚开机也不会白丢一段；查不到（老宿主 / 库读坏）就退回内存。

窗口可跨零点（`"22"-"2"`）。落在多个窗口时只取第一个命中的段——默认三段不重叠。

## 安装

开发时在 `data/extensions/package.json` 里指到仓库：

```json
"world-idle-nudge": "link:C:/…/jingxi-coopanion-worlds/packages/idle-nudge"
```

改完让宿主重装一次，再到 World 总览里打开。装完先保持关着，把 `idleMinutes` 按你自己上游的缓存有效期调好再开（LongCat-2.5 默认 40 能用；别的模型见 `cache-keepalive` 包里的 `scripts/measure.ts`）。

## 与 cache-keepalive 的关系

本插件的静默心跳是 `cache-keepalive` 那份判据搬过来的（同一台机器实测过）。原来的 `cache-keepalive` 可以卸掉——它做的事这里全包。**先验证新插件跑通，再卸旧的。**
