# 变更记录

## 0.3.0（2026-11-26）

- **判据改成「要推之前查事件库」**：宿主把事件库开给了 World（`host.store.range`，同步、按 `source` / `senderKey` / `fromTs` 过滤）。仍然先用内存判，**只有判据说要推的那一刻**才查一次「今天自己推过什么」，查到的结果写回内存并立刻重判一次——所以同一件事最多查一次，下一拍内存就拦住了（正常一天几十次查询，不是每 15 秒一次）。
- 每次推送带稳定 `senderKey`：`note:0` / `greeting:1` / `beat`（宿主会把它连同 `meta` 一起落库，见 `loop.ts` 的 `store.append`）。下一拍按它认身份。
- 顺带解决了 0.2.6 那个别扭的补丁：原来「抖动点在启动前就过了 → 当天不补」，代价是晚开机就白丢一段；现在是「今天这一段推过才不推」，**晚开机照样推**，重启也不会重复（内存与库取 max/OR，因为刚推的事件要等投递才落库）。
- 问候也一并受益：重启不再重发当天已经发过的早安 / 晚安（0.2.5 时只能靠内存）。
- 现状卡的数字（今天几张 / 几拍 / 几条）重启后也是对的，不再是「重启归零」。
- 查不到（老宿主没有 `store`、库读坏了）就退回纯内存：宁可多推一条，也不要因为查询失败一整天不推。
- 测试 69 个全绿（world 层改成注入假事件库：已推过 → 不推；没推过 → 照推；问候同理；另加两条——没到点一次都不查、要推时只查一次）。

## 0.2.9（2026-11-26）

- 修「跨零点又补一条晚安」。17788 控制台实测：11-25 23:12:07 推了一条 `idle-nudge.greeting`，11-26 00:00:09 **同一次运行**（`run` 相同，不是重启）又推了一条。
- 根因：`decideGreeting` 用 ±720 分钟归一化算「目标距现在多久」，把「今晚 23:35 的目标」在 00:00 看成「15 分钟前」，于是落到「刚过点 + 60 分钟宽容」里直接补一条。改成用**同一天的原始差**（目标在 0–1439 内取模，正数＝今天还没到）。
- 顺带：只开了一条问候时，现状卡说「今天的晚安已经发过了」，不再说「两条问候都发过了」（早安没填会误导成两条都在跑）。
- 代价写进注释：目标点落在 00:0x（把时刻填到 23:5x、抖动跨了零点）的那天不补，等第二天按新日期的目标走。
- 测试 67 个全绿（新增 2 个：跨日不重复、单条问候的现状文案）。

## 0.2.8（2026-11-25）

- **写盘遇到坏 `config.json` 改成「拒绝写回」**，和宿主 `readJsonObject` 一字不差（它抛「config.json解析失败,拒绝写回(请手工检查文件)」）。原来是「先留底、再从空对象重建自己的段」——那等于把别的 world 的段全抹掉。本机实测这份文件里有 20 来个别的段（星邮 `tokenSecret`、Server 酱 `sendkey`、shell 的执行配置…），所以这条必须收紧。
- 顶层不是对象（`[]`、`"x"`）也拒绝：数组会被 `JSON.stringify` 写成 `[]`，字符串会静默丢掉别的键。
- `config.json` 不存在＝新装，照常建一份（只有「存在但坏了」才拒绝）。
- 坏文件时设置页显示「没有保存：config.json 解析失败，先手工修好它（插件不会拿空对象重建）」，输入框内容保留（`dirty`）。
- 测试 65 个全绿（新增 3 个：坏文件拒绝且原文不动、顶层非对象拒绝、新装照建；world 层加了「坏文件时保存报错、别的段一个字没动」）。

## 0.2.7（2026-11-25）

- 设置页保存改成**严格校验**（新增 `src/validate.ts`）：写坏了当场报错，这一份**一个字都不存**。之前是悄悄回退/夹逼——填 `9-25` 退回旧时段、填 `999` 夹成 240、填 `25:00` 保留旧时刻，界面还显示「已保存」，人以为改上了。
- 拦下的情况：时段/时刻写坏（`9-25`、`25:00`）、半填（`9-`）、起止相同（`9-9`）、超出范围的整数（看表间隔 1、每日上限 999…）、小数、正文超过 500 字。报错带位置，如「时段 2只填了一半「9-」：两端都要填，要不整行留空」。
- 报错显示在设置页底部（宿主把插件的异常翻成 500 + `{error}`，前端去掉 `Error:` 前缀）；输入框内容不会被清（`dirty` 保留），改对了再失焦就存。
- **读盘仍然是软的**：`readSettings` 继续用 `clampSettings` 兜底，手改坏的 `config.json` 不会让插件起不来。严格只针对「刚提交的那一份」。
- 测试 62 个全绿（新增 3 个：严格校验的两组用例、坏值不落盘）。

## 0.2.6（2026-11-25）

- 修「每次重启都白递一条纸条」。17788 控制台实测（`/api/events`，看 `run` 换没换）：11-25 16:33–17:57 之间 7 次重启，7 条 `idle-nudge.note`，全部落在启动后 16–23 秒。根因是运行时状态只在内存（`lastNoteAt` / 每段名额重启归零），而抖动点按「日期|段号|第几张」算、重启后还是那个已经过去的点。现在 `decideNote` 顺带返回 `targetAt`（抖动点的绝对时刻），World 用本会话开始时刻（`startedAt`）比一下：**抖动点在启动前就过了的，当天不补**——重启不再重复递，一直开着的时候行为不变（新增 2 个测试）。
- 早晚安两行的提示词写明「按行算，不按钟点猜」：第一行固定早安、第二行固定晚安，17 点道早安、3 点道晚安照填就照跑（新增 1 个测试锁住）。
- 保存**失败**时不再清 `dirty`：清了之后 3 秒轮询会把服务端旧值写回输入框，刚敲的内容看着像存上了其实被刷掉。现在失败保留保护、下次失焦再存一次。
- 时段框半填（`9-`）原样显示成 `9-`，不再显示为空让人以为没填过。
- `writeSettings` 遇到坏 `config.json` 时先把原文留一份 `config.json.broken-<时间戳>` 再重建自己的段（全插件共用一份 `config.json`，重建会带走别的 world 的段）。
- 测试里 `tickTwice` 改名 `tickOnce`、删掉没人用的 `getLastNoteAt`。
- 测试 59 个全绿。

## 0.2.5（2026-11-25）

- 修「早安没发出去，晚安一整天推不出来」：`decideGreeting` 原来用 `findIndex` 只取第一条「启用且没发过」的问候，早安没发（早上没开机、中午才开开关、那次推送失败）就一直占着候选位，22:30 报的是「今天的早安约在 07:35，还有 545 分钟」。改成逐条算，命中窗口的按最先到点的那条推；都没命中才挑「今天稍晚」的报时间。
- 修「晚上把已过的问候说成还没到」：`minutesUntil` 的 ±720 归一化在 19:36 之后会把 07:35 的早安算成 +719 分钟。现在只有 target 确实比当前晚才算「还有 N 分钟」，绕了一圈的按今天错过处理（跨零点、窗口几分钟后就开的仍按到点处理）。
- 修「推送失败饿死后面两套判据」：问候 / 纸条推不出去时原来直接 `return`，判据状态又不推进，于是每拍都命中同一个、每拍都失败，心跳永远轮不到。现在失败降级到下一套，纸条失败还有心跳兜底续缓存。
- 修「现状卡不刷新」：`webui.js` 的只读行没注册 writer，轮询每 3 秒只走 `sync`，三行现状永远停在面板打开那一刻。现在只注册 writer（不进 `collect`，不会被当参数存回去）。
- `usage.jsonl` 的 mtime 改到每拍开头读：「缓存距今多久」那颗药丸不再因为问候 / 纸条那一拍提前返回而显示上一拍的值。
- 关总开关 / 没挂到宿主时一并更新问候那行的现状文案（原来只有心跳和纸条两行变）。
- `slotEnabled` 把 `9-9` 这种起止相同的窗口当没填（`inWindow` 本来就是恒 false，原来会显示「已启用」却一张都不推）。
- 心跳英文默认句改用 `beat.ts` 的 `DEFAULT_TEMPLATE_EN`，不再在 `world.ts` 里另抄一份。
- `webUi()` 返回处补 `as WorldWebUiDecl`（`badges` 不在包能读到的类型里，不加断言 `tsc` 会报多余属性）；删掉未使用的 `clampMaxPerDay` 导入。
- `package.json` 补 `typecheck` 脚本（`tsc --noEmit`），和别的包对齐。
- 测试 53 个全绿（新增 5 个：晚安不被早安挡住、晚上不报「还有 N 分钟」、早安错过文案、纸条失败降级心跳、问候+纸条失败降级心跳）。

## 0.2.3（2026-11-25）

- 修「填了时刻、显示已保存、但时刻没存进去」：根因是 §4.7 的焦点保护只覆盖「正在敲」，没覆盖「失焦 change → 600ms 防抖存盘」这个窗口——轮询在这 600ms 内回写了服务端的旧空值，`collect()` 时 DOM 已被刷回空。加 `dirty` 集合，防抖期间的字段跳过回写；保存成功/失败/结构重建时都清 dirty。

## 0.2.2（2026-11-25）

- 正文提示写明 `{time}` 是抖动后真正发出去的时刻，不是框里填的点——前后最多差一个幅度。

## 0.2.1（2026-11-25）

## 0.2.0（2026-11-25）

- 新增第三个功能「早晚安」（`greetingEnabled`，默认关）：两个时刻各一行（左时刻、右双向抖动幅度），时刻留空不启用；默认幅度 ±20 分钟可改。
- 到点后由她在窗口内挑一个时刻，用 `idle-nudge.greeting` 事件递一句让她发给 ta 的问候；正文模板可改，默认写明「不是 ta 刚说的、别回这条、照常驻通道发给 ta」，带 `{time}` / `{who}` 占位符。
- 复用小纸条那套哈希抖动（同一天稳定、隔天换），窗口形状从「一段区间」换成「一个点 ± 幅度」；一天一条，过了窗口不补，防止半夜补昨晚的晚安。
- 三套判据同一拍都通过时按 问候 > 纸条 > 心跳 取一条，缓存照样续、不重复唤醒。
- 设置页卡片顺序：小纸条 → 早晚安 → 静默心跳 → 现状；现状卡与页头药丸/侧栏灯都加上问候。
- 48 个测试全绿。

## 0.1.5（2026-11-25）

- 新增插件「小纸条」（`world-idle-nudge`）：闲下来时按节奏推一条事件，两套判据独立。
- 静默心跳：距上次模型调用超过阈值就补一拍，续上游前缀缓存，全天生效；默认关——缓存命中不便宜或 TTL 不稳的模型开了反而更贵，设置页写明风险。
- 小纸条：三个可配时段，每段独立限额，窗口内按「日期 + 段号 + 第几张」哈希抖动出随机时刻（当天稳定、隔天换），不看 `usage.jsonl` 的 mtime，后台推再多信息也挡不住它。
- 两套判据同一拍都满足时纸条优先，把心跳计时记成现在，缓存照样续、不重复唤醒。
- 页面：小纸条 → 静默心跳 → 现状三张卡；两个功能各自开关在卡首；时段每行两个并排框（左时段、右张数）；正文框提示写明默认句；页头药丸与侧栏灯显示现状。
- 纸条正文写成陈述式并标明「不是 ta 说的、别回这条、要做就调工具」——问句会被当成有人在跟她说话，诱使她用气泡回复。
- 设置存进 `config.json` 的 `worlds.idle-nudge.settings`，与开关同住一份文件；运行时状态只在内存，不写盘、不碰数据库。
- 36 个测试全绿（纯函数 + 设置读写 + world 集成）。
