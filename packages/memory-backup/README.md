# coopanion-world-memory-backup

[Coopanion](https://github.com/Pal-AI-Lab/Coopanion) 的记忆备份，一个 Cortico World 扩展：到点提醒 bot 整理 Memory，整理完把数据目录复制成一份带时间的备份；需要时可以把其中任意一份写回去。

> 为 Coopanion 的数据目录布局编写，只在 Windows + Coopanion 上验证过。裸 Cortico 部署、macOS 与 Linux 都未测试。

## 它做什么

- **提醒**：按每天固定时刻或固定间隔提醒它整理 Memory，提醒里写明记忆目录的规模、上次整理和上次备份。应用关着时错过的那次，下次启动补送。
- **整理完就备份**：它整理完调用一次工具，这个扩展记下它写了什么，并在同一次调用里把数据目录复制一份。复制这段时间它不写文件。
- **回滚**：可以把任意一份快照写回去，范围是记忆、插件（连依赖）、插件设置与凭据。
- **保留**：默认留最近 5 份，更旧的自动删除，只删带自己清单的文件夹。

## 快照的是哪个目录

默认（`scope` 为 `data`）是应用的数据目录，Windows 安装版在：

```
C:\Users\<你>\AppData\Local\Programs\Coopanion\data
```

Steam 版、macOS、Linux 分别是 `%APPDATA%\Coopanion`、`~/Library/Application Support/Coopanion`、`~/.config/Coopanion`。其中的：

| 子目录 | 内容 | 是否复制 |
|---|---|---|
| `home/` | 记忆与对话记录、设置、各家密钥、语音模型、运行时 | 复制（模型与运行时默认跳过） |
| `extensions/` | 装进来的插件，连同它们各自的依赖 | 复制 |
| `logs/` | 日志 | 复制 |
| `tmp/`、`pnpm/`、`Crashpad/`、Electron 的缓存目录 | 临时文件与缓存 | 不复制 |

最后一行恢复时用不上，整份复制只会让每份备份多出几百 MB；要连它们一起，把 `scope` 设成 `custom`、目录填数据目录本身。

`scope` 为 `deployment` 时只复制这份部署（`home/companion/`：记忆、对话、设置），不含密钥与模型。

## 快照到哪里

默认是用户主目录下：

```
C:\Users\<你>\Coopanion\memory-backups\2026-10-27_21-00-00\
```

在安装目录之外，卸载或重装程序不会连备份一起删。`backupDir` 可以改成任意目录。每份快照里是 `home/`、`extensions/`、`logs/` 和一份清单 `.memory-backup.json`(文件数、体积、bot 写的备注、被截断或被占用的文件)。

## 复制正在写的文件会不会坏

不会变成半截的坏文件。这些文件只有三种写入方式：

| 写入方式 | 文件 | 复制的结果 |
|---|---|---|
| 写临时文件再改名 | 设置、密钥、唤醒与通知记录、工作区里的每个记忆文件 | 一定是完整的旧版或完整的新版 |
| 逐行追加 | 事件、日志、用量记录 | 前面的行完好；最后半行会被截掉，恢复后最多丢最后几条 |
| 下载到 `.partial` 再改名 | 语音模型、运行时 | 要么是完整的旧文件，要么是还没下完的临时文件（不复制） |

复制发生在工具调用期间，这时 bot 停在那次调用上，不写自己的文件。仍在变的文件会在备份里留下它那一刻的样子，并在清单里注明。

## 回滚

对 Coo 说「回到上周那份」，它会用 `mb_restore`；也可以直接给出快照文件夹的路径。

- **两步**：不带确认时只给预览——有几个文件、会覆盖什么、记忆里哪些多出来的文件会被删；带了才写。
- **范围**:`memory` 只回记忆，`extensions` 回插件这一整套，`both`(默认)两边都回。
  - 记忆以快照为准，快照里没有的文件删掉；工作区的 `.git` 既不覆盖也不删除，恢复出来是一次待提交的改动。
  - 插件连同依赖一起回来；各插件的开关与参数、`.env` 里的密钥、`data/` 下插件自己的 token 与状态也一起回来。
  - 正在执行回滚的这个扩展自己不回滚（它的包、设置、状态都保持原样）。
- **不动**：对话记录与事件库、会话与用量日志，以及联机插件在服务器上的记录。
- **联网插件**：会把本地状态上报的插件（比如生态箱），回滚后可能把当时的数据再报一次；不想这样就让 `target` 用 `memory`，或先关掉它的上报。
- **先存再改**：每次回滚前自动把当前状态另存一份，回执里给出位置；后悔时用那份再回滚回来。
- **生效要重启**：文件写完就落盘，但要重启 Core 才重新加载。可以让 Coo 调 `mb_restart`(桌宠断开几秒)，或在设置窗口的扩展页点「重启进程」。

### 在新机器上恢复

回滚按**这台机器的布局**找位置（记忆在 `<数据目录>/home/companion/workspace`，插件在 `<数据目录>/extensions`），快照当初来自哪台机器、哪个路径都不影响。

1. 新机器装好 Coo，把这个扩展装上，先启动一次让它建出自己的数据目录。
2. 把快照文件夹整个拷过去，放在能读到的地方。
3. 让 Coo「从 `<路径>` 恢复记忆和插件」，看过预览再确认。
4. `mb_restart` 或扩展页「重启进程」。

插件设置会一起过来；端点的选择与密钥、对话记录、工作区的 Git 历史不跟过来。

## 安装与设置

1. 设置窗口的高级模式 →「扩展」→ 本机目录，选这个包的目录；或从市场按包名安装。
2. 「重启进程」。
3. 高级模式 →「World 总览」里启用「记忆备份」。同一页的「停用」会把整个扩展关掉：提醒停止，工具从 bot 手里撤走，已备份的文件不动。
4. 点进「记忆备份」，在「配置」页签里设提醒时间与备份范围，改完即生效。

只想关提醒、保留手动备份：把「提醒时机」设成「不提醒」。

## 配置

| 键 | 默认 | 含义 |
|---|---|---|
| `schedule` | `daily` | 每天固定时间 / 固定间隔 / 不提醒 |
| `dailyAt` | `21:00` | 本地 24 小时制；夏令时跳过的时刻顺延 |
| `intervalMinutes` | `1440` | 固定间隔时的分钟数，30 到 43200 |
| `scope` | `data` | 数据目录里的 `home`、`extensions`、`logs`；或只这份部署；或自定义目录 |
| `customRootDir` | 空 | 自定义目录的绝对路径 |
| `backupDir` | 空 | 空则用 `<用户主目录>/Coopanion/memory-backups` |
| `maxBackups` | `5` | 保留份数 |
| `skipModels` | `true` | 跳过语音模型与运行时；关掉则每份快照都带上，换机器不必重新下载 |
| `memoryDir` | `workspace` | 记忆目录，相对部署目录；只用于提醒里报规模 |
