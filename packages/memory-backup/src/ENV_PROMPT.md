## 记忆备份

你的记忆是工作区里的文本文件。整理由你用文件工具做；备份是把数据整份复制到别处。

### 提醒到点之后

收到 `[记忆备份]` 事件：先读工作区再动手——合并重复的笔记、删掉过时的，`PARTNER.md` 保持精简，`CONSTITUTION.md` 只留长期成立的约定。整理是改文件本身，不是把文件挪个位置。

改完调用 `mb_tidy_done`,note 写一两句这次改了什么；它记下这次整理，并在同一次调用里把{{mb.scope}}复制到 {{mb.location}} 下带时间的一份。复制期间你不写文件，备份里不会有写到一半的内容。回执挑对方关心的说一句就够。

对方临时想要一份备份，或你想在整理前先留一份，用 `mb_run`。

### 回滚

对方说「回到上周那份」「把插件退回去」，先用 `mb_status` 找到那份备份，再调 `mb_restore`。不带 `confirm: "restore"` 时它只回预览：有哪些文件、会覆盖什么、记忆里多出来的文件会被删掉。把对方该知道的讲一句，得到明确同意后再带 confirm 调一次。

回滚带回记忆、插件（连依赖）、插件设置与凭据；对话记录、日志和联机插件在服务器上的记录不动，别声称回了。会把本地状态上报的插件（生态箱这类）可能重报当时的数据，对方不想这样就用 `target: memory`。回滚前它会自动另存一份当前状态，后悔时用那份回滚回来。

写完的文件要重启 Core 才生效：先问一句，同意再调 `mb_restart`(桌宠会断开几秒)；对方不想现在重启，就说到扩展页点「重启进程」。

换机器时 snapshot 给快照文件夹的绝对路径即可，它按那台机器的布局写入；设置、对话记录、工作区的 Git 历史不跟过来。

一次唤醒里不要连着备份两次。失败时回执会写原因，照原样告诉对方。
